# Earthquake OLAP Explorer

[![ETL + Deploy](https://github.com/Dayan-18/earthquake-olap-duckdb-wasm/actions/workflows/deploy.yml/badge.svg)](https://github.com/Dayan-18/earthquake-olap-duckdb-wasm/actions/workflows/deploy.yml)

A **serverless OLAP solution**: two years of global earthquakes (USGS, M2.5+) are modeled as a **star schema**, stored as **Parquet**, and analyzed **inside the browser** with **DuckDB-WASM**. A GitHub Actions workflow rebuilds and redeploys everything every day. There are no servers, no databases to maintain, and no AWS.

**Live dashboard:** https://dayan-18.github.io/earthquake-olap-duckdb-wasm/

## Architecture

```
 USGS FDSN API ──► GitHub Actions (daily cron) ──────────────────────────► GitHub Pages ──► Browser
 (public, no key)   ├─ Extract   : Python + requests, 1 call per month        (static)        DuckDB-WASM
                    ├─ Transform : DuckDB SQL → star schema                                  runs the SQL
                    ├─ Load      : Parquet (ZSTD)                                             (OLAP engine)
                    ├─ Validate  : 10 data quality checks (fails the deploy)
                    └─ Deploy    : upload-pages-artifact → deploy-pages
```

| Layer | Tool | Why |
|---|---|---|
| Source | USGS Earthquake Catalog API | Public, real-time, no API key |
| Processing | Python 3.11 + DuckDB | Columnar SQL engine, no cluster needed |
| Storage | Parquet + ZSTD | Columnar, compressed (~2 MB for 58k events) |
| OLAP engine | DuckDB-WASM | Vectorized analytical SQL in the browser |
| Automation | GitHub Actions | On push, daily schedule and manual run |
| Hosting | GitHub Pages | Free public SaaS hosting |
| Visualization | Chart.js + Leaflet | Charts and map |

## Star schema

```
                 dim_date                      dim_magnitude
          (date_key, year, quarter,      (magnitude_key, class,
           month, iso_week, day_name)      min_mag, max_mag)
                        \                     /
                         \                   /
   dim_region ──────── fact_earthquake ──────── dim_depth
 (region_key,        (event_id, date_key,      (depth_key, class,
  region_name,        region_key, magnitude_key, min_km, max_km)
  country)            depth_key, magnitude,
                      depth_km, lat, lon, ...)
```

- **Fact grain:** one row per earthquake (`event_id`, deduplicated by the latest `updated` version).
- **Measures:** `magnitude`, `depth_km`, `stations`, `azimuthal_gap`, plus `count(*)`.
- **Hierarchies:** year → quarter → month → week → day, and country → region (US states, Mexican regions, and so on).

## OLAP operations in the dashboard

| Operation | Where |
|---|---|
| **Slice** | Filter by a single country or depth class |
| **Dice** | Date range + minimum magnitude + country + depth combined |
| **Roll-up / Drill-down (time)** | "Time grain" selector: year ↔ quarter ↔ month ↔ week ↔ day |
| **Drill-down (geography)** | Click a country bar to see its regions |
| **Pivot** | Depth × magnitude class matrix with totals |
| **CUBE / ROLLUP / windows** | Example queries in the SQL console |

The SQL console accepts any DuckDB SQL against the five tables, for example:

```sql
SELECT d.year, d.quarter, count(*) AS events, round(avg(f.magnitude), 2) AS avg_mag
FROM fact_earthquake f
JOIN dim_date d USING (date_key)
GROUP BY ROLLUP (d.year, d.quarter)
ORDER BY d.year NULLS LAST, d.quarter NULLS LAST;
```

## Run locally

```bash
pip install -r requirements.txt
python etl/pipeline.py --days 730 --min-mag 2.5   # extract + transform + load
python etl/validate.py                            # data quality checks
python -m http.server 8000 --directory web        # open http://localhost:8000
```


## Deploy your own copy

1. Fork the repository.
2. Go to **Settings → Pages → Source: GitHub Actions**.
3. Run the **ETL + Deploy OLAP dashboard** workflow, or push to `main`.
